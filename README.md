# NMTF

Does a random-walk transform help orthogonal NMTF embed a protein interaction network?
This project factorises a human physical protein-protein interaction network (STRING v12) with
orthogonal non-negative matrix tri-factorisation, once from the network's random-walk PPMI and
once from its plain adjacency matrix, and compares the clusters by Gene Ontology enrichment and by
stability across random starts. Result in one line: PPMI clusters recover more GO terms and
are far more stable (see `reports/nmtf-report.qmd`, rendered by `pixi run reproduce`).

Author: keqin peng ([ORCID 0009-0000-1487-1227](https://orcid.org/0009-0000-1487-1227))
Course project for CBIO7501 (Reproducible and Open Science), Fall 2026.

## Reproduce the results

You need [Pixi](https://pixi.prefix.dev/latest/) and an internet connection (about 26 MB of raw data).
Then, from this folder:

```bash
pixi install --locked   # builds the exact environment recorded in pixi.lock
pixi run reproduce      # tests, downloads the raw data, rebuilds every result, renders the report
```

`pixi run reproduce` must work on a fresh clone of this repository. A GitHub Action
(`.github/workflows/reproduce.yml`) checks that on every push. Settings (network size, number of
clusters, seeds, thresholds) are in `config/config.yaml`; change them there, not in the code.

## The seven questions

1. **What is the project about?** A small, fully reproducible version of the PPI embedding analysis of
   the Pržulj group: PPMI versus adjacency input for orthogonal NMTF, judged by GO enrichment of the
   clusters and by agreement between random seeds.
2. **Is there a related publication?** No paper of this project. The method follows
   Xenos et al. 2021 ([doi:10.1093/bioinformatics/btab487](https://doi.org/10.1093/bioinformatics/btab487)) and
   Doria-Belenguer et al. 2023 ([doi:10.1093/bioinformatics/btad281](https://doi.org/10.1093/bioinformatics/btad281)).
3. **What does the repository contain?** See the table below.
4. **What hardware does it need?** Any laptop or runner: CPU only, no GPU, about 400 MB of memory at the
   peak, about 3 minutes on 2 CPU cores for the analysis, plus the downloads and the Pixi installation.
5. **How do I reproduce the analyses?** `pixi install --locked` and `pixi run reproduce`, as above.
6. **What outputs should I expect?** `reports/nmtf-report.html` (the report) and in `results/`:
   `metrics.csv` (one row per input and seed), `convergence.csv`, `stability.csv`, `top_terms.csv`.
   `data/processed/` holds the gene network (`edges.tsv`, `genes.tsv`), the GO annotations and
   `summary.json`. All of them are rebuilt by the code and are not committed.
7. **How do I contact the authors or discuss the project?** Open an
   [issue](https://github.com/callmepikachu/NMTF/issues) or write to pkqpikachu@gmail.com.

## What is where

| Folder | What goes in it | Rule |
|--------|-----------------|------|
| `data/raw/` | STRING and GO files exactly as downloaded | Read-only. Downloaded by `scripts/download_data.py`. Not committed. |
| `data/processed/` | Gene network and GO annotations made from the raw data | Regenerated by code. Not committed. |
| `metadata/` | Sources (URL, SHA-256, license) and checksums of the raw files | Small text files, committed. |
| `scripts/` | Code: download, data preparation, NMTF library, embedding run | Committed. |
| `config/` | Parameters of the analysis | Committed. |
| `tests/` | Unit tests on small synthetic networks and an end-to-end test on fake raw files | Committed. |
| `reports/` | The Quarto report and its references | Source committed, rendered HTML not. |
| `results/` | Tables made by the analysis | Regenerated. Not committed. |
| `docs/` | Decision log | Committed. |

Each folder has its own `README.md` with more detail.

## Data

Raw data are three public files, none of them stored in this repository:

- STRING v12.0, human physical links and protein info, <https://string-db.org> (license CC BY 4.0) [^1].
- UniProt-GOA human annotations (`goa_human.gaf.gz`) of the Gene Ontology release 2026-05-19,
  <https://release.geneontology.org/2026-05-19/> (license CC BY 4.0).

Source URLs, SHA-256 checksums and licenses are in `metadata/sources.tsv`. Download and verify them with
`pixi run download` (or `sha256sum -c metadata/checksums.sha256` after downloading). Derived data
(`data/processed/`) and results (`results/`) are rebuilt from the raw data by the project code and are not
archived separately.

[^1]: STRING v12 is described in Szklarczyk et al. 2023, [doi:10.1093/nar/gkac1000](https://doi.org/10.1093/nar/gkac1000). Cite STRING and
the Gene Ontology ([doi:10.1093/genetics/iyad031](https://doi.org/10.1093/genetics/iyad031)) if you reuse the data.

## Data availability

The raw data are public and archived by their providers (STRING consortium; Gene Ontology Consortium and
UniProt-GOA). The exact files used here are identified by URL and SHA-256 in `metadata/sources.tsv`. The
GO release is pinned to the dated archive 2026-05-19, so the same file can be downloaded later. All
code to rebuild the processed data and results is in this repository, and a release (git tag) marks the
version of the code and the lock file behind the report.
